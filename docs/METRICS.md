# PULSE — метрики, эксперименты, Go/No-Go

**Редакция 0.1 / 21.10.2026.** Цели ниже — начальные продуктовые гипотезы для закрытого теста, не отраслевые бенчмарки и не прогнозы.

## North Star: качественно проведённый вечер

**Weekly Successful Social Sessions (WSSS)** = число сессий за 7 дней, где пользователь провёл ≥5 минут в реальной комнате с ≥3 другими совершеннолетними участниками, дал «нейтрально/хорошо» по добровольной оценке и не имел серьёзной нерешённой жалобы на эту сессию. Если оценка не дана, учитывать отдельно в `unrated sessions`, не скрывать denominator. Проверить чувствительность метрики к bias отвечающих.

## Основные KPI

| Метрика | Определение | Стартовая цель беты |
|---|---|---:|
| Activation | % новых 18+ участников, вошедших в реальную комнату за первые 24ч | ≥45% |
| First-match p50 | медиана от нажатия «войти в вечер» до фактического подключения, в заданные окна активности | ≤60 сек |
| Session completion | % вошедших, оставшихся ≥5 минут | ≥40% |
| D1 retention | % пользователей когорты дня N, активных в день N+1 | ≥30% |
| D7 retention | % пользователей когорты дня N, активных в день N+7 | ≥15% |
| Mutual contact | % активных участников, добровольно создавших ≥1 взаимный контакт за 7 дней (после S2) | ≥15% |
| Positive feedback | % ответивших, выбравших «хорошо», с учётом доли ответивших | ≥70% |
| Severe incidents | подтверждённые угрозы/домогательства на 100 session-hours | тренд вниз, **нет нерешённых P0** |
| Balanced wait p90 | 90-й перцентиль ожидания в opt-in 50/50 (по сегментам) | измерять; не скрывать долгие очереди |

Цели по retention невалидны при очень малых когортах; обязательно указывать знаменатель/доверительные интервалы и количество дней наблюдения.

## Event taxonomy / без содержимого переписки

```text
onboarding_started, age_gate_passed, rules_accepted, profile_completed,
event_viewed, queue_joined, queue_cancelled, queue_timeout,
match_offered, match_confirmed, room_joined, room_left,
prompt_viewed, prompt_skipped, message_sent_aggregate,
voice_joined, voice_left, consent_revoked,
feedback_submitted, contact_requested, contact_mutual,
report_submitted, block_created, moderation_action_taken,
account_deletion_requested
```

События включают только псевдонимизированный пользовательский ID, event/room ID, безопасный временной штамп и ограниченные технические категории. **Не логировать текст сообщений, точные координаты, email и чужую гендерную идентичность** в аналитическом потоке.

## Safety guardrails / критические остановки

- Любой подтверждённый P0 инцидент с активной угрозой без доступного процесса реагирования → приостановить соответствующую функцию.
- Невозможность блокировать/репортить или обход block ACL → остановить бета-приглашения до исправления.
- Резкое увеличение жалоб на одну категорию → ручное расследование, не автоматически объявлять успех по retention.
- Нет реально подключённых людей в запланированный слот → явно показывать недостаток аудитории, не подменять ботами.
- Жалобы и уход женщин/других групп анализировать без публичного раскрытия чувствительных данных и без дискриминационных решений.

## Эксперименты

1. Слот начала: 20:00 vs 21:00, сравнивать при достаточных cohort sizes.
2. Разогрев: вопрос vs короткая мини-игра vs свободный чат.
3. Группы 4 vs 6 (отдельно качество и стоимость голоса).
4. Степень анонимности: шаблонные аватары vs псевдонимы без аватара.
5. Open vs balanced opt-in: не мерить лишь количество матчей; проверить ожидание и отсутствие нежелательных контактов.

## Go / Iterate / Stop (после 100–300 участников)

- **Go ограниченный:** нет открытых P0; измеряется реальная аудитория; качественные сессии и D7 достигают целевых диапазонов, расходы посчитаны.
- **Iterate:** хорошая обратная связь, но люди не находят друг друга — уменьшить количество одновременно доступных тем/слотов.
- **Stop/pivot:** опасные сценарии системно неуправляемы либо люди не возвращаются после нескольких циклов мероприятий.

Все решения документировать с выборкой, периодом наблюдения и альтернативным объяснением результата.
