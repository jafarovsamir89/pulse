# PULSE — техническое задание (PRD v0.2)

**Утверждённое направление (21.10.2026):** близкий функциональный аналог Litmatch с оригинальным UX и кодом. Этот документ **заменяет v0.1**, где первым сценарием были комнаты по расписанию. **Текущий репозиторий пока не содержит рабочего сервиса.**

## 1. Суть продукта

PULSE — 18+ социальное приложение для быстрого ненапряжённого общения, анонимного перед другими участниками по умолчанию: короткий текстовый матч 1:1, позже голосовой матч, маленькие вечеринки, взаимные контакты, затем лёгкая лента и безопасные встречи. Северная звезда — **реально состоявшийся комфортный разговор**, а не просмотры профилей или продажи подарков.

Ключевой референс: [Litmatch](https://play.google.com/store/apps/details?id=com.litatom.app). Похожий функционал, но без чужой графики/названий/кода, платной покупки доступа к собеседнику, обязательного фото и имитации онлайна. [Feature matrix](LITMATCH_FEATURE_MATRIX.md).

## 2. Платформы и аудитория

- Первая платформа — **Web/PWA**, 18+, одна языковая когорта (RU или AZ решаем после тестов), опора на реальные окна присутствия.
- **Android** — после стабильной закрытой беты и отдельной проверки Google Play policy.
- **iOS** — без обещаний: Apple §1.2 запрещает или может удалить приложения, используемые преимущественно как random/anonymous chat. Возможна необходимость существенного изменения продукта; решение только после юридического/policy review.
- Камера, публичная биография, фамилия и фото необязательны. Нельзя позиционировать PULSE как медицинское лечение одиночества.

## 3. Приоритеты функционала

**P0 / Alpha — реализуемая вертикаль:**
- Age-gated аккаунт/сессии, соглашение, псевдоним, язык, абстрактный аватар.
- **Text Match:** мгновенный запрос, честная очередь, атомарное формирование пары из реальных 18+ пользователей с совместимым языком, подтверждение, короткая беседа, завершение; стартовая тема.
- **Двустороннее согласие** на сохранение контакта; без unsolicited DM. Контакт после match может писать собеседнику, до этого — нет.
- Block/report/leave/mute, защита от спама, разграничение прав, базовая модерация + аудит, account deletion, метрики без текста сообщений.
- Минимальные **текстовые Party Rooms**, если это не тормозит безопасный запуск 1:1: отдельная следующая вертикаль P0.5, не требуется для первого end-to-end.

**P1 / Voice & Parties:**
- **Voice Match**: короткий звонок с отдельным согласием, RTC token по membership, mute/leave/block/report, без фоновой записи.
- **Party Rooms:** текст/голос 4–6 реальных участников, темы и лёгкие игры, роли ведущего и модератора, очередь микрофона; добровольные open/balanced комнаты, invite-link с TTL.
- **Avatar** расширения, экран взаимных связей и повторного общения.

**P2 / Moments:** модерируемая лента коротких текстовых моментов/интересов; исключить ранние неподконтрольные фото, прямой публичный рейтинг и платную видимость.

**P3 / Outings:** только после успешного safety gate, реальные встречи небольшими группами в публичных местах, город только по opt-in, проверенные организаторы. Не в MVP.

## 4. Сценарии и критерии приёмки

### UC-01 Быстрый Text Match

1. 18+ пользователь проходит вход, принимает правила и заполняет псевдоним/язык.
2. На главном экране жмёт **«Найти собеседника»** и при желании задаёт настроение.
3. Сервер создаёт не более одной активной заявки, проверяет age-gate status, бан, blocklists, ограничение скорости и совместимость языка. Можно безопасно отменить.
4. Система предлагает пару из **двух реальных пользователей** и получает подтверждения с ограниченным TTL; неподтверждённые места освобождает.
5. После подтверждения обоих появляется краткий текстовый чат; клиент **не может** читать/писать в чужой сессии. Один человек может выйти/пожаловаться в любой момент.
6. После завершения оба независимо выбирают «Продолжить общение?»; только две положительные реакции создают контакт, при отказе не сообщаем другому причину.
7. Если никого нет, видим честное ожидание/предложение присоединиться к модерируемой комнате или вернуться позже; никаких fake users.

**AC-1:** в production невозможно присоединиться к матчу без одобренного age-gate / действующей сессии. **AC-2:** пользователь не участвует сразу в двух матчах/комнатах. **AC-3:** пары не формируются с заблокированным участником. **AC-4:** повторная сетьвая попытка идемпотентна. **AC-5:** DM отсутствует до mutual consent. **AC-6:** abuse/report и выход работают всегда.

### UC-02 Voice Match (P1)

Участник отдельно выбирает голос, получает системный диалог разрешения микрофона, кратковременный scoped token и управление mute/leave/report. При бане и block доступ к голосу прекращается. Нет записи и автоматической публикации. При техническом сбое честное сообщение, нет скрытого включения микрофона.

### UC-03 Party Rooms (P0.5 текст / P1 голос)

Тематическая комната на 4–6 человек; список реальных присутствующих, доступные свободные места, тема, текст, необязательный импульс, mute, leave, report. В voice beta — очередь микрофона/host-kick с RBAC. Сбалансированный формат только после прямого выбора, 2/2 или 3/3 при достаточном числе участников; при отсутствии — ожидание или open только по согласию.

### UC-04 Приватный профиль и связи

Публично: псевдоним, опциональные интересы, аватар-пресет. Не показывать IP, номер, email, точную локацию, приватную гендерную идентичность. Экспорт/удаление аккаунта. Пользователь может отозвать контакт и заблокировать.

### UC-05 Moments и Outings (позже)

Моменты публикуются только с UGC фильтрами и report/block. Офлайн — публичные места, организатор/операционный контроль, отдельная юридическая оценка.

## 6. Ограничения и антизлоупотребления

- **Нельзя обещать глобальное 50/50**: неравные онлайн-числа делают это математически невозможным. Общая аудитория и Text Match не закрываются по бинарному признаку; balanced 2/2 и 3/3 — отдельная добровольная разновидность групп.
- Не поощрять платную покупку внимания, гендерную привилегию, подарки за деньги, публичный рейтинг красоты или массовые DM.
- Не хранить пол/гендер и точную геолокацию без законного основания и явной продуктовой необходимости. Никакой обязательной биометрической проверки пола.
- Не подменять отсутствие пользователей AI-ботами. Демо-аккаунты только изолированно и помечены.
- Сначала safety gate и человеческий moderation workflow — потом реальный публичный чат.
- iOS-риск, защита персональных данных, локальные права и музыка рассматриваются отдельно и требуют review.

## 7. Метрики и решение о запуске

Измеряем p50/p90 ожидания Text Match (только в объявленные часы), фактические разговоры ≥5 мин, взаимные сохранения, D1/D7, rate жалоб на 100 session-hours, потери сессий, расходы на пользователя, gender-balanced queues и удовлетворённость. Цели/формулы: [METRICS.md](METRICS.md). После беты 100–300 человек — Go/Iterate/Stop, не автоматический масштаб.

## 8. Архитектура и границы

React/TS/Vite + NestJS + Prisma/PostgreSQL + Redis + Socket.IO; WebRTC/LiveKit позже. Сервис хранит идентичность приватно и запрещает читать чужие сессии. Описание конкретных моделей и API: [ARCHITECTURE.md](ARCHITECTURE.md). Код пишется в отдельной ветке, с тестами, без секретов.

## 9. Определение готовности MVP

Продукт считается живой alpha **только когда** два разных одобренных 18+ тестовых аккаунта на двух клиентах через сервер могут пройти Text Match → обменяться сообщениями → завершить → взаимно сохранить контакт → успешно отправить DM, а без взаимности DM запрещён. Дополнительно: действуют блокировка, жалоба и реальные модераторские инструменты; 0 известных P0 security defects. Старый `spikes/matchmaker.mjs` не удовлетворяет этому DoD.
