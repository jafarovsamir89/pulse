Подробный состав диапазонов и альтернативная стоимость труда — [BUSINESS_PLAN](../BUSINESS_PLAN.md). Нужны реальные предложения провайдера возраста/юриста/reviewer. Если они выше резерва, менять план до трат.

## Порядок проверок

1. Чистая alpha и рискованные lifecycle cases — P01.
2. Ручная понятность/удовольствие — P02/P03, параллельно ремонту.
3. Один законченный G1 без голоса/магазина — P04.
4. Допуск/операции/данные/backup — P05.
5. Живой ограниченный G1, зрелые cohorts — P06.
6. Только затем автоматизация доказанной пользы группы/круга.

G1 нужен без круглосуточного ведущего; модератор остаётся доступным в объявленные часы. Для ручных тестов ведущий нужен, его влияние протоколировать. Нельзя считать постоянное бесплатное шоу основателя свойством движка.

## Go / Iterate / Stop

Единые численные gates в [METRICS](../METRICS.md), не дублировать конкурирующие пороги. Низкая выборка требует продолжения наблюдений, а не маркетингового «доказали». Safety gate жёсткий независимо от размера выборки. После двух содержательных итераций слабого ядра не добавлять новые режимы в надежде скрыть проблему.

Ближайший отдельный engineering prompt — [CODEX_FIRST_SPRINT](../CODEX_FIRST_SPRINT.md). Этот документационный пакет не запускает production и не тратит бюджет.
