# UX и социальные механики

**25.10.2026.** Текущий UI проверен локально; будущий сценарий — предложение, не готовые макеты и не результат пользовательского теста. Метод: Product Design Audit, screenshot-first. Исследование ограничено существующей авторизованной dev-сессией; onboarding, handshake, реальный диалог и мобильный viewport в этом прогоне не подтверждены.

## 1. Текущий опыт: наблюдение → последствие

Скриншоты сняты в этом исследовании на localhost:5173, desktop viewport 1280×720. Первые два сохранены с crop y=100, 1280×620, чтобы не публиковать псевдоним в шапке. Это изображения alpha PR №1, не экраны предлагаемого pivot.

### Шаг 1. Главный экран

![Главный экран alpha, crop без шапки](evidence/01-home.jpg)

Сохранить: один основной призыв, спокойный тон, взаимное согласие как часть объяснения. Проблемы: большая декоративная область конкурирует с полезным состоянием; обещание «обычно несколько минут» не подкреплено наблюдаемой статистикой/расписанием. Disabled Rooms занимает место до появления ценности. На маленьком экране нужны отдельные тесты: desktop-наблюдение не доказывает mobile usability.

### Шаг 2. Нажатие поиска

![Состояние после попытки поиска](evidence/02-search-unavailable.jpg)

Backend вернул 503, DOM содержит английский `Safety rate limit is unavailable`. Это проверено действием в браузере, а не выдуманный empty state. Нижняя фиксированная навигация перекрывает часть нижнего feedback/подсказки в наблюдаемом окне; сам текст ошибки лучше читается в DOM, чем на crop. Серьёзность **высокая**: основное действие не достигает результата, сообщение техническое и плохо заметно. Предложение: различать «нет участников», «сервис временно недоступен» и «поиск начат»; показывать понятный следующий шаг в видимой области. Не обходить fail-closed защиту ради красивого демо.

### Шаг 3. Connections

![Пустые Connections](evidence/03-connections-empty.jpg)

Пустой экран объясняет взаимное согласие, но не даёт прямого полезного следующего шага кроме возврата. Серьёзность **средняя**: новый пользователь снова должен искать маршрут. Предложение: «Записаться на ближайшую встречу» и короткое описание того, как появится контакт. Не подставлять фиктивные карточки друзей.

По коду дополнительно: в alpha нет полной dark theme/reduced-motion поддержки, множество подписей 9–11px, часть action targets мала, Contacts не имеет законченных safety controls. Это **code observations**, не результаты замера контраста или screen-reader аудита. Проверки клавиатуры, screen reader, text zoom 200%, контраста и слабого Android остаются до пилота.

## 2. Новая архитектура опыта

Три основные вкладки: **Сегодня → Круги → Я**. «Сегодня» содержит один ближайший подходящий слот, тему, длительность, реальную доступность и ведущего. «Круги» содержит предстоящие повторные встречи и взаимные контакты, без публичных счётчиков популярности. «Я» — псевдоним, язык, доступность, статус допуска, privacy, помощь и удаление. Служебные состояния не превращаются в новые разделы.

Основные экраны: объяснение формата; вход/возраст и альтернативный review; выбор языка/окна; карточка встречи; подтверждение участия; lobby с правдивым составом; сессия; безопасный выход/жалоба; приватное согласие на продолжение; предложение следующего окна; круг/контакт; профиль/настройки; история обращения. Формирование группы — работа сервиса, не длинный каталог пустых комнат.

### Путь во времени

Чувства в таблице — ожидаемые состояния для проверки, не установленные реакции. «30 секунд» не обещает завершить законную проверку возраста или найти живую группу за этот срок.

| Момент | Что видно | Ожидаемое чувство / действие | Где уйдёт | Как снижаем трение / добровольная причина вернуться |
|---|---|---|---|---|
| 0 секунд | «20 минут в небольшой компании», ближайшее реальное время, 18+, без обязательного фото | Любопытство, понимание цены участия | Неясно, dating ли это; тревога публичности | Чёткое «дружеское общение», формат и право выйти; без ложного «все уже ждут» |
| 30 секунд | Язык, окно, тема; объяснение приватной проверки допуска | Может представить вечер и начать вход | Слишком много полей или неожиданная камера | Запрашивать только нужное; объяснить проверку до разрешения; честно показать длительность и альтернативу |
| 2 минуты | При завершённом допуске — запись/lobby; иначе понятный pending status | Чувство контроля, подтверждение участия | Нет мест, верификация зависла, непонятная ошибка | Ближайший другой слот, отмена одним действием; не показывать чужие данные pending пользователю |
| 10 минут | Живая сессия, первый маленький вклад каждого, общий объект/вопрос | Достаточно безопасно участвовать | Доминирующий участник, пустота, слабая сеть | Ведущий/очередность без принуждения, skip, text fallback, reconnect status, exit/report |
| 30 минут | Сессия завершена; приватный выбор продолжения и два окна | Я сам решаю, хочу ли снова | Давление «не обижай компанию», слишком много действий | Отказ никому не показывается; по умолчанию нет раскрытия контактов; завершённый приятный опыт уже ценен |
| Следующий день | Итог только при согласии: согласовано время / пока нет состава | Предсказуемость, одна конкретная договорённость | Спам напоминаний или отсутствие результата | Одно opt-in уведомление; можно отменить. Не обязателен ежедневный вход |
| Первая неделя | Повторная встреча с частью знакомого состава | Узнаваемость, меньше неловкости | Те же вопросы, неявка, слишком сильная закрытость | Новое совместное действие; подтверждение присутствия, честная отмена; новые участники только с согласием |
| Первый месяц | Один-два устойчивых круга, виден следующий план | Принадлежность и самостоятельность | Устали, перешли в другой мессенджер, нет времени | Пауза без наказания; инструменты координации; экспорт своих данных/контактов по разрешённому процессу |

Низкая частота может быть здоровым исходом. Ежедневный streak конфликтует с обещанием приятной компании по свободному времени; D1 уступает значимости состоявшемуся R7/R28.

## 3. Отдельные продуктовые поверхности

| Поверхность | Основной экран и действие | Safety / offline / empty |
|---|---|---|
| Text Match | Если сохраняется контрольный 1:1: одна тема, честное ожидание, два независимых accept, статус отправки, завершение | Leave/block/report всегда доступны; нет таймера, вынуждающего раскрыть контакт; pending message явно не доставлен |
| Voice Match | Позже: предварительный тест микрофона, явное согласие, mute по умолчанию до входа, текстовый fallback | Не запрашивать mic до намерения; нет записи; reconnect не включает микрофон неожиданно; выход сразу |
| Party Rooms | Сначала маленькие назначенные встречи: вместимость, роль ведущего, настоящее число вошедших, тема и время | Нет каталога сотен пустых комнат; поведение хоста тоже можно обжаловать; очередь речи добровольная |
| Connections / Круги | Предстоящий план и знакомая группа; взаимные контакты отдельно от приглашения на событие | «Сохранить контакт» и «пойти снова» — разные согласия; revoke/block/report в той же поверхности |
| Profile / Я | Псевдоним, preset avatar, язык/окно, правила/статус возраста, доступность, приватность | Никаких доходов/рейтингов; редактирование, logout всех устройств, удаление/статус запроса, помощь с допуском |

Нельзя показывать имена участников отказавшемуся или ещё не допущенному пользователю. Инвайт на событие не раскрывает состав и не обходит возраст. Ссылки ограничены по сроку/назначению, вход проверяется сервером.

## 4. Почему нужен общий предмет разговора

У незнакомых людей нет общей истории, непонятна допустимая глубина раскрытия, неловко начать и легко принять тишину за отказ. Это рабочие гипотезы для интервью. Исследование Hall связывает проведённое вместе время и определённые виды общения с развитием близости, но не доказывает, что игра или 20 минут гарантируют дружбу. Не превращать усреднённые часы из наблюдательных исследований в таймер «друг разблокирован». [Hall, online 15.03.2018 / выпуск 2019](https://doi.org/10.1177/0265407518761225).

### Отбор механик

Старт/повтор: 1–5, больше лучше. Разработка/риск замещения дружбы: 1–5, больше хуже. Это design judgment, не результаты испытаний. Сначала проверить текстовыми карточками у ведущего.

| Механика | Начать разговор | Повтор | Сложность | Риск «игра вместо связи» | Решение |
|---|---:|---:|---:|---:|---|
| Один лёгкий вопрос с правом пропустить | 4 | 2 | 1 | 1 | **Выбрать** для разогрева, менять темы |
| Совместно спланировать вымышленный маленький проект/вечер | 5 | 4 | 1 | 2 | **Выбрать**: общий объект снижает интервьюирование друг друга |
| Правда или блеф о безопасной вымышленной истории | 4 | 3 | 2 | 2 | **Выбрать**, без проверки личных тайн, денег и отношений |
| Продолжение коллективной истории на следующей встрече | 3 | 5 | 2 | 2 | **Выбрать**, без обещания награды за обязательный возврат |
| Угадай коммерческую песню | 4 | 3 | 4 | 3 | Отложить: права/доставка аудио, сильнее оценивает музыкальный капитал |
| Публичный командный турнир | 4 | 4 | 4 | 5 | Отложить: рейтинги и победа легко вытесняют контакт |
| Тайное задание воздействовать на другого участника | 3 | 2 | 2 | 4 | Отвергнуть: манипуляция/недоверие; допустимы лишь полностью раскрытые добровольные задания |
| Музыкальная комната с ведущим | 4 | 4 | 5 | 4 | Позже при правах, спросе, операциях |
| Большая тематическая вечеринка | 3 | 4 | 4 | 4 | Позже: холодный старт и доминирование сцены |
| Свободный разговор без структуры | 2 | 3 | 1 | 1 | Контрольный вариант, не обязательная игра |
| Ежедневная серия заданий/streak | 2 | 3 | 2 | 5 | Не внедрять; возврат должен быть к людям |

Четыре выбранные механики — **набор альтернатив**, не четыре обязательных уровня каждой сессии. 20–25 минут: 2 минуты объяснение/выход, 3 минуты разогрев, 8–10 минут одно совместное действие, 5–8 минут свободное общение, 2 минуты приватное завершение. Можно отказаться от игры и остаться в разговоре.

### Механика PULSE: «Вторая встреча»

Общее действие оставляет маленький добровольный повод продолжить: например, компания придумала маршрут вымышленного выходного и хочет обсудить варианты. Это не искусственный cliffhanger. После выхода человек отдельно выбирает продолжение, контакты и доступные окна. Сервис согласует время, скрывая индивидуальные отказы, и предлагает вторую встречу. Полная логика состава и consent — [PULSE_VISION_V2.md](PULSE_VISION_V2.md).

Проверка: случайное назначение простой структуры против свободного разговора, одинаковый ведущий/время; исход — не очки игры, а добровольный повтор, распределение участия, комфорт и доля «меня вынуждали говорить». Если больше минут в игре сопровождаются меньшим R7, игру убрать. Если все возвращаются только к ведущему, это другой продукт — клуб ведущего, с другой экономикой.

## 5. Два визуальных направления

| Направление | Образ и система | Сильная сторона | Риск |
|---|---|---|---|
| A «Тихая гостиная» | Тёплый нейтральный фон, графитовый текст, один фиолетовый акцент, простые геометрические аватары, крупный план встречи | Спокойный взрослый формат, совместим с текущей alpha, меньше графического/энергетического расхода | Может выглядеть скучно; компенсировать конкретной темой и живыми деталями событий, не шумом |
| B «Ночной пульс» | Тёмная сцена, яркие цветные орбиты, динамика вокруг голоса, более игровая идентичность | Подходит вечерним party/voice и коротким промороликам | Ассоциации с шоу/флиртом, визуальная нагрузка, дорогая анимация и пустая сцена |

**Выбор A.** Он поддерживает желаемое спокойное участие и текущий бюджет. Оригинальность создавать последовательностью экранов, тоном, ритуалом продолжения и своей графикой, а не копированием Litmatch. Dark theme — полноценные контрастные токены того же направления, не инверсия цветов. Предлагаемые токены для прототипа: light background `#F6F5F1`, foreground `#242721`; dark background `#171A18`, foreground `#F4F5F0`; accent проверить на контраст в каждом назначении.

## 6. Критерии качества для следующего UX-прогона

- Базовый текст 16px, вторичный преимущественно ≥14px; target около 44×44 CSS px как проектное требование. Проверить реальный контраст, не объявлять соответствие по палитре.
- Keyboard focus, labels, status announcement без постоянного чтения секунд очереди, screen reader, zoom 200%, reduced motion. Смысл не передаётся только цветом.
- Минимальные opacity/transform переходы 120–180ms; никакой постоянной анимации, когда вкладка скрыта. Не блокировать выход анимацией.
- Начальная загрузка без тяжёлого видео/3D; измерить bundle, LCP/INP и память на недорогом Android. Целевые бюджеты для прототипа: initial JS ≤200KB gzip, LCP ≤2,5s на оговорённом тестовом профиле, отсутствие заметного роста памяти после 10 циклов вход/выход. Это цели, не текущие результаты.
- При слабой сети показывать connected/reconnecting/offline, сохранять краткий локальный черновик с понятной очисткой, не показывать сообщение отправленным до ACK. Не держать скрытый микрофон/фоновые polling циклы без необходимости.
- Проверить полную цепочку с двумя взрослыми тестовыми клиентами, третий синтетический отрицательный клиент, rotate/background/reconnect, timeout и report. Текущее screenshot-наблюдение не заменяет этот gate.

Дешёвый usability-тест: 5–8 взрослых из целевой когорты выполняют «найти встречу», «понять, кто видит профиль», «выйти и пожаловаться», «отказаться от продолжения», «найти знакомую компанию». Считать ошибку задания, время и объяснение своими словами; не принимать похвалу эстетике за доказательство понятности.
