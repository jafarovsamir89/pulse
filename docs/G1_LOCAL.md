# «Угадай меня» — локальный игровой прототип

Реализовано: комната по ссылке, два настоящих участника, 6 раундов «свой ответ → прогноз → раскрытие» и 7-й общий финал. Точные догадки дают одно очко внутри партии. Есть реакции, пропуск без раскрытия/штрафа, более медленный темп, +15 секунд, пауза при бездействии, выход и взаимный реванш с новым game ID и свежими карточками из колоды из 24 авторских черновиков.

## Запуск

Нужны установленные workspace dependencies, Node 22+, pnpm 10 и локальный PostgreSQL с подготовленной dev DB. Обычный `.env` по `.env.example` подходит для Compose из репозитория. `pnpm dev:game` проверяет loopback URL и имя dev DB **до** генерации Prisma и применения локальных миграций, затем запускает web на 5317 и API на 3107. Не использовать production DB. Команда откажется работать с `NODE_ENV=production`, удалённой БД или именем вне `pulse`/`pulse_local`.

На текущей машине PostgreSQL уже работает на 55479. Запуск из корня:

```sh
DATABASE_URL=postgresql://macbookair@127.0.0.1:55479/pulse_local \
REDIS_URL=redis://127.0.0.1:6389 pnpm dev:game
```

Открыть [игру](http://localhost:5317/), ввести имя, подтвердить 18+ и создать комнату. Отправить ссылку или открыть приглашение во второй вкладке через кнопку в комнате. Во второй вкладке нужен отдельный участник; оба нажимают «Я готов». Credential сохраняется в `sessionStorage` каждой вкладки, в ссылке его нет. Дублирование вкладки браузером может скопировать её sessionStorage: для второго игрока использовать именно новую вкладку/кнопку приглашения. Закрытие вкладки теряет этот локальный credential; обновление вкладки сохраняет его.

Ссылка доступна только на этой машине: API при включённом локальном режиме слушает 127.0.0.1, guard запрещает production и внешние подключения. Для игры с другого устройства понадобится отдельный разрешённый пилотный запуск с настоящим admission; текущий режим туда не переносить.

## Что делает сервер

- `LocalGameRoom` хранит состояние в Postgres. Каждый переход блокирует строку комнаты, проверяет credential участника, game/round ID, версию и фазу. Вход третьего участника запрещён.
- Клиент получает только свою проекцию: чужие ответы, прогнозы, будущая колода и token hashes не отправляются до раскрытия. Очки считаются по раскрытым раундам, поэтому score не выдаёт скрытый ответ.
- Повтор command ID с тем же смыслом не применяет ход заново; изменение payload запрещено. Последние 200 квитанций ограничивают локальный размер состояния. Stale version получает 409; UI обновляет состояние и повторяет тот же command ID только в том же раунде/партии.
- Дедлайны принадлежат серверу. Таймаут не выбирает ответ за человека. Два пропуска по бездействию вызывают проверку присутствия; через 30 секунд без возврата встреча заканчивается. Переходы обрабатываются при чтении/команде, отдельный background scheduler не требуется для локального прототипа.
- Обновление страницы восстанавливает принятые ходы из БД. Polling примерно 550 мс в активной и 1400 мс в фоновой вкладке; это проверяемый локальный transport, не production replay/outbox.
- Комнаты имеют срок доступа 24 часа; при создании следующей удаляются истёкшие **только LocalGameRoom**. Это не решение production retention/deletion из открытого T10.

## Проверки и границы

Unit state-machine и real local DB/API E2E проверяют скрытие данных, таймаут/skip, неверную фазу/опцию, идемпотентность, гонку команд, все семь раундов, очки, взаимный реванш, восстановление и production gate. UI проверен двумя независимыми вкладками от приглашения до финала и реванша, с обновлением вкладки после выбора.

Это локальная проверка игровой идеи. Self-declared 18+ не является серверной верификацией возраста; карточки ожидают независимой редакторской проверки и пользовательских испытаний. Нет свободного чата, голоса, DM, знакомства с незнакомцами и монетизации. Старые T04/T05/T07/T09–T13 Text Match остаются открытыми. Alpha сохранена отдельно в `?alpha=1`; обычный вход открывает игру.
